# 단계별 이전 계획

구현을 시작할 때는 [작업 목록](TASKS.md)에서 다음 ID와 해당 작업의 검증 기준을 확인한다.

각 행은 독립적인 검토 단위다. v1 명령과 메뉴를 사용할 수 있는 상태에서 다음 단계로 넘어간다. 기준 동작과 변경 압력은 [현황 및 목표 구조](ARCHITECTURE.md)에, 실행 가능한 기준 검사는 [테스트 지침](TESTING.md)에 기록한다.

| Phase | 변경 범위 | 완료 판정 |
|---|---|---|
| 0 현황 분석 | 기준 리비전과 기존 테스트 결과 기록, 계약·계획·작업 지침 작성 | 문서에서 현행과 제안을 구분할 수 있고 주요 설계 선택을 사용자가 검토할 수 있다. |
| 1 Core | setup 진입점, CLI, 메뉴를 분리하고 Registry·기본 Runner를 기존 함수 어댑터에 연결 | 기존 7개 테스트 통과. 중복 ID, 누락 함수, source 실패 시 실행 전 종료. help와 메뉴 번호·인자 오류 보존. |
| 2 모듈 | workspace·iterm부터 git·shell·node·python, 마지막으로 github·repository 순서로 이동 | 각 이동마다 해당 기존 테스트 통과. 같은 목표 재적용, 다른 버전, 진단 오류와 verify 실패를 검증. clone/remote 전용 옵션과 거부 동작 보존. |
| 3 설정 | classroom/minimal, 계정 설정 하위 호환, 모듈별 키와 검증 훅 및 배열 스냅샷 도입 | 선택 목록·옵션 우선순위 검증. 기존 profiles와 INSTALL_* fixture 통과. 잘못된 새 값·제거한 키가 메뉴의 마지막 정상 설정을 오염시키지 않는다. |
| 4 Shell | 로더·활성 목록·모듈별 조각 및 기존 env.zsh 이관 | 기존 .zshrc 보존, 이중 source 후 PATH 한 번, 비활성 조각 제외, 사용자 편집 파일·링크 거부, 중간 실패 후 재시도 검증. |
| 5 실행 계획 | plan/dry-run, 의존 순서 및 결과 요약, list·메뉴·도움말 연결 | 잘못된 계획은 첫 쓰기 전에 중단. 실패 의존 항목은 BLOCKED, 독립 항목은 완료. dry-run 전후 HOME 비교 및 설치 명령 호출 0회 확인. |
| 6 확장성 | 임시 복제본에만 예제 모듈과 환경 fixture 추가 | Core·메뉴·로더 수정 없이 list/help/메뉴 노출, 옵션 검증, plan/check/apply/verify, 재실행 SKIPPED를 확인. 후속 실제 도구 추가의 기준으로 사용. |
| 7 안정화 | 호환 어댑터 정리, 사용자 안내·운영 한계 갱신, iMac 수동 점검 | 기준 교육장 Intel iMac에서 전체 회귀와 T21 실기 조건 충족. 일괄 관리 중에도 OS·OpenSSH 버전이 달라 다른 장비 조합과 실제 초기화 후 복원은 사용 시점에 검증한다. 다운로드 출처·검증 가능한 고정 버전과 체크섬·서명, 실패 정리 경로를 도구별로 리뷰. [T21 완료 조건](TASKS.md) |

기존 설치 함수의 호출부부터 이동하고 동작 수정은 해당 모듈 단계로 한정한다. 실패가 발생하면 해당 단계와 기존 명령을 직접 재현한다. 새 도구 설치, 병렬 실행, 영속 실행 이력은 초기 이전 범위 밖이다. Phase 0 검토 후 첫 구현 대상은 CLI 분리와 workspace 어댑터를 통과하는 최소 Runner 경로다.
