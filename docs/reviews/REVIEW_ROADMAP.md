# Dev Bootstrap 코드 책임 로드맵

## 1. 책임의 정의

코드를 직접 작성했는가보다 **동작을 설명하고, 검증 범위를 구분하고, 실패를 통제할 수 있는가**가 중요하다. AI가 작성한 코드는 외부 기여 코드와 동일한 기준으로 검토한다.

## 2. 권장 5단계

1. **의도**: 요구사항과 금지 동작(예: 기존 SSH 키 삭제 금지)을 작성한다.
2. **구조**: 진입점, 호출 그래프, 모듈 책임을 설명한다.
3. **계약**: 입력, 출력, 부작용, 실패, 재실행 동작을 명시한다.
4. **증거**: 단위/통합/모의/실기기 테스트를 구분하고 테스트가 증명하지 못하는 것을 기록한다.
5. **운영**: 오류 로그, 실패 후 복구, 자격 증명 폐기, 버전 및 변경 이력을 관리한다.

## 3. 1주일 학습 계획

| 일자 | 읽을 범위 | 산출물 |
|---|---|---|
| 1일 | `setup.sh` | 명령별 호출 흐름 그림 |
| 2일 | `lib/`, `git.sh` | 설정 우선순위와 Git 계약 기록 |
| 3일 | `auth/ssh.sh`, `auth/gh.sh` | 인증/보안 위협 목록 |
| 4일 | `repository.sh`, `workspace.sh` | 데이터 보존 시나리오 |
| 5일 | `node.sh`, `python.sh`, `shell.sh`, `iterm.sh` | 외부 설치/의존성 위험 목록 |
| 6일 | `tests/` | 요구사항-테스트 증거 매트릭스 |
| 7일 | 실제 macOS | 수동 검증 기록과 우선 개선 작업 3개 |

## 4. AI에게 리뷰를 요청할 때

> 다음 함수의 입력, 출력, 부작용, 실패 경로, 재실행 시 동작을 실제 코드에 근거해 설명해 줘. 추정은 추정이라고 표시하고, 관련 테스트가 무엇을 증명하고 무엇을 증명하지 못하는지 구분해 줘. 위험도가 높은 부분부터 질문을 만들어 줘. 코드 수정은 아직 하지 마.

## 5. 변경 승인 기준

- 목적과 범위를 설명할 수 있다.
- 기존 파일/설정을 파괴하지 않는다는 근거가 있다.
- 변경한 기능의 자동 테스트와 관련 회귀 테스트가 통과한다.
- 외부 시스템 의존 기능은 모의 테스트와 실제 검증을 구분한다.
- 남은 위험, 되돌리기 방법, 재검증 절차가 기록되어 있다.
