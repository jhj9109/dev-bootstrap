# v2 구현 작업 목록

번호 순서가 기본 선행 순서다. 각 행은 작업 범위와 완료 조건을 정의한다. 공통 작업 절차는 [에이전트 지침](../AGENTS.md)을 따른다.

## Phase 1 · 기존 명령을 통해 Core 연결

- [x] **T01 · CLI와 메뉴 분리.** `setup.sh`의 인자 처리와 대화형 메뉴를 각각 `core/cli.sh`, `core/menu.sh`로 옮긴다. 기존 설치 함수를 그대로 호출한다. 두 진입점의 help, 잘못된 인자의 종료 코드 2, 메뉴 2번의 설정 재로딩, 0번 종료를 확인한다.
- [x] **T02 · Registry와 첫 모듈 등록.** 저장소 내부의 `modules/*/module.sh` 탐색을 시작 경로에 연결하고 workspace를 등록한다. 중복 ID, 필수 함수 누락, 로드 실패를 각각 주입해 사용자 파일을 쓰기 전에 종료하는지 확인한다.
- [x] **T03 · Workspace를 Runner로 실행.** 기존 `configure workspace` 요청을 check → apply → verify로 연결한다. 임시 HOME에서 첫 실행은 디렉터리를 만들고 두 번째는 건너뛰어야 한다. 진단 오류 시 apply 호출 0회, 변경 후 검증 실패 시 비정상 종료를 확인한다.

## Phase 3~4 · 설정과 셸 이관

Phase 3은 T11~T13, Phase 4는 T14~T15다.

| 완료 | ID | 변경 범위 | 완료를 보여주는 검사 |
|---|---|---|---|
| ☐ | T11 | 모듈별 설정 키·기본값·검증 등록과 원자적 스냅샷 | 모듈 키 하나를 추가해 로더 수정 없이 반영. 잘못된 후보값 거부 후 마지막 정상 상태 보존 |
| ☐ | T12 | classroom/minimal 선택, 환경 배열, 기존 INSTALL_* 변환 | 같은 계정에서 서로 다른 대상 목록 선택. CLI 명시 값 우선, 기존 all fixture 통과 |
| ☐ | T13 | 계정 파일 이전 및 메뉴 재로딩 | profiles.conf 단독 호환, accounts.conf와 동시 사용 시 우선순위, 삭제한 필드 초기화 |
| ☐ | T14 | 셸 조각 로더와 기존 env.zsh 전환 경로 마련 | 임시 HOME에서 알려진 v1 파일을 이관하고 편집 파일·링크 보존. 전환 실패 후 다시 적용 가능 |
| ☐ | T15 | Node·Python 초기화를 각 모듈 조각으로 이동하고 활성 목록 연결 | 새 셸에서 요청 도구 사용, 두 번 로드해 PATH 중복 없음, minimal에서 비활성 조각 제외 |

T14에서는 기존 도구의 초기화 내용을 보존한 채 전환 경로를 시험한다. T15에서 활성 조각이 준비된 후 기본 실행 경로를 새 로더로 전환한다.
